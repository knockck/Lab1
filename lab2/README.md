# Лабораторная работа № 2 · вариант 19

Проверка и поиск синтаксически корректного полного пути к файлу в Windows.
Программа проверяет путь с клавиатуры и находит такие пути в текстовом файле.
Для найденных вхождений выводит номера строк и столбцов, начиная с 1.

## Запуск

Нужен Python 3.9 или новее. Запускайте команды из корня репозитория.
Программа использует стандартную библиотеку Python.

```bash
python -m lab2
python -m unittest discover -s lab2/tests -v
```

1. Для проверки введите `1`, затем путь, например `C:\Учёба\Отчёт.docx`.
2. Для поиска введите `2`, затем `lab2/example.txt`. Должно быть 4 совпадения.
3. Для выхода введите `0`.

В Windows можно заменить `python` на `py`. Поиск читает UTF-8 (в том
числе с BOM) и UTF-16 с BOM.

## Формализация

```text
Путь     = Корень { Каталог Разделитель } ИмяФайла
Корень   = Буква ":" Разделитель
         | Разделитель Разделитель Узел Разделитель Ресурс Разделитель
Каталог  = Имя | "." | ".."
ИмяФайла = Имя
```

| Элемент | Правило |
|---|---|
| Диск и разделители | Латинская буква, двоеточие и разделитель. Поддерживаются `\` и `/`. |
| UNC | Узел задан непустыми метками из букв, цифр, подчёркиваний и внутренних дефисов, разделёнными точками. Далее идут имя ресурса и минимум один компонент пути к файлу. |
| Обычные имена | Непустые. Допустимы Unicode, внутренние пробелы и точки. Конечный пробел или точка запрещены. |
| Запрещённые символы в именах | `< > : " / \ \| ? *` и U+0000–U+001F. |
| Имена устройств | `CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`, включая варианты с ¹, ², ³. Регистр и расширение не меняют правило. |
| Размер | До 255 единиц UTF-16 в компоненте. Общая длина зависит от API и конфигурации Windows. |
| Последний компонент | Имя файла обязательно. Расширение можно опустить. `.` и `..` допустимы в промежуточных каталогах. |

Модель охватывает обычные абсолютные пути диска и UNC. Относительные
пути, пространства имён устройств и расширенных путей (`\\.\`,
`\\?\`), и альтернативные потоки данных выходят за рамки задания.
Проверка определяет допустимость записи. Существование файла, права
доступа и тип конечного объекта зависят от файловой системы.

Регулярное выражение собрано из именованных фрагментов в
`windows_paths.py`. `fullmatch()` проверяет строку целиком.
Отрицательная опережающая проверка `(?!...)` исключает имена устройств.
Отдельный подсчёт проверяет длину в единицах UTF-16.

## Поиск в тексте

- Путь на отдельной строке может содержать пробелы. Отступ вокруг него
  считается оформлением строки.
- Внутри текста путь с пробелами пишите в двойных кавычках.
  Например, `Копия "C:\Мои документы\Отчёт.docx"`.
- Внутри текста пути без пробелов разделяйте пробелами. В конце такой
  записи допустима запятая или точка с запятой. Парные скобки вокруг
  пути служат обрамлением. Если знак входит в имя файла, используйте
  двойные кавычки. Кавычки также отделяют путь от точки в конце фразы.

Сначала проверяется строка целиком. Затем `finditer()` выделяет
кандидаты, а `is_valid_path()` применяет к ним то же выражение, что и в
режиме ручного ввода. Программа хранит позицию начала каждого совпадения.

## Структура файлов

| Файл | Назначение |
|---|---|
| `windows_paths.py` | Регулярное выражение и проверка пути. |
| `search.py` | Поиск в тексте, вычисление координат и чтение файла. |
| `cli.py`, `__main__.py` | Меню и точка запуска. |
| `example.txt` | Файл для демонстрации поиска. |
| `tests/` | Тесты выражения, поиска и консольного меню. |
